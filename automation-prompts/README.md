# 如何更新两个 Cursor 定时任务 Prompt

打开 https://cursor.com/automations ，分别用以下文件全文替换 Prompt 并保存：

| 任务 | 粘贴文件 |
|------|----------|
| 盘中实时简报（A股实时简报） | `PROMPT_盘中实时简报_可粘贴.txt` 或 `PROMPT_intraday_paste.txt` |
| 晚间深度简报 | `PROMPT_晚间深度简报_可粘贴.txt` 或 `PROMPT_evening_paste.txt` |

云端 Artifacts 英文文件名更容易打开：
- `/opt/cursor/artifacts/PROMPT_intraday_paste.txt`
- `/opt/cursor/artifacts/PROMPT_evening_paste.txt`

## 当前模块

1. 近两日 Memories + **上一轮预测对照**
2. 宏观政策 / 国际形势 / 机构资金（P）
3. **市场情绪仪表盘**（涨跌家数、涨停/炸板、成交、情绪分）
4. **跟热点选真主线**（资金 + 涨停结构 + 资讯 → 续涨确定性 → 时间窗）；不再锁定长鑫/存储
5. 当日热点产业链上中下游
6. 公告业绩
7. 催化与海外映射（有则写，无固定个股日报）
8. **分组池 + PACE+ 打分卡片**（进攻 / 观察 / 低吸 / 回避）
9. **虚拟账户：50 万 + 港股通 + 创业板/科创板**；激进高仓位；每周滚动盈亏总结
10. 数据健康度；每轮 1 封终稿

已删除：长鑫科技（688825）每日跟踪附录、长鑫链专节、强制半导体/存储主线。

## 预测框架（来自常见 A 股 skill 的可执行部分）

- PACE+：政策 20 / 资金 25 / 技术 25 / 情绪 20 / 催化 10，映射偏多概率与三情景
- 短线研报式分组与个股卡片（触发、观察区、失效、仓位）
- 预测 vs 实盘对照，写入 Memories 供下一轮校正

## 虚拟账户要点

- 初始/口径 500,000 元；若 Memories 仍为 10 万口径：现金 +400,000，持仓不变，只增资一次
- 交易时段内可模拟成交；非交易时段只更新市值 + 写下一时段意向委托
- 风格激进：单票默认 50%（极强 60%–70%），总仓位 90%–100%；进攻池必须尽量落地
- 每轮输出完整快照 + 【最近一周盈亏与操作总结】

## 发信防刷屏（2026-10 修复）

排查发现 Resend 请求全是 200，没有 API 报错；"失败邮件"来自定时任务自己用占位/测试内容调用发信工具（正文是 `PLACEHOLDER_WILL_FAIL`、`TEST_SHORT_DO_NOT_SEND`、`PLACEHOLDER_SEE_FILE` 等，主题却是真实简报标题），晚间任务 14 分钟内发了 6 封。

Prompt 已改：只传 text 不传 html（参数减半）、正文 ≤ 约 9000 汉字、严禁占位/测试发信、必须带 idempotencyKey、失败最多静默重试 1 次、已受理即视为成功。

## v3 优化（2026-10 基于成熟 skill）

审计发现 10-06 至 10-09 的盘中简报正文几乎全是 PLACEHOLDER 空壳，原因是发信参数太大（HTML+纯文本各一份，且先在对话里写一遍再发，输出量翻 2–3 倍）。

借鉴来源与落地：
- a-stock-predictor（PACE 分维打分、概率与盈亏比、止损目标）：PACE+ 分项评分细则、E(r) 与盈亏比准入门槛、ATR 推导止损/目标
- a-share-short-decision（决策日志、预测对照实盘、无信号强制说明）：预测台账 LEDGER + 分档命中率 STATS，下一轮结算
- a-share-short-term-trading（决策卡、分组池、数据健康度）：决策卡置顶、四组池、数据健康度
- TradingAgents（多空辩论后必须表态、风险裁决、反思教训注入）：多空裁决一行、组合止损暴露上限、LESSONS 滚动 10 条并回注
- 数据纪律：来源优先级与双源校验、行情滞后检测、账户对账公式

发信：只发 text、盘中 ≤3500 汉字 / 晚间 ≤6000 汉字、不先在对话里写正文、禁止占位、三档降级（完整→压缩→仅决策卡）。
